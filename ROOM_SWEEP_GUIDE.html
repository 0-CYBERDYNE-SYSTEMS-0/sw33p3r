01

What this is

Room Sweep answers one question: "is anything in this room transmitting right now?" It sweeps a fixed list of frequencies and bands commonly used by analog bugs, wireless cameras, and trackers, and separately listens for WiFi access points and Bluetooth devices via an external radio.

RF Survey, Band Sweep, Peak Refine, WiFi, and BLE are receive/monitor paths. The dedicated TX tab is separate, starts disarmed, and requires deliberate arm and transmit actions. Use it only on authorized equipment and frequencies.

Path A — Sub-GHz RSSI sweep (built in)

The Flipper's internal CC1101 hops across 16 ISM/surveillance channels, averages 8 RSSI samples per channel, and draws a live bar chart. Any channel above −75 dBm fills solid, prints SIGNAL!, and lights the red LED. Needs no external hardware.

Path B — Marauder over UART (external)

An ESP32 (the "BFFB" board) running Marauder firmware connects to the Flipper's USART at 115200 baud. The app sends scanap (WiFi APs) or sniffbt (BLE) and parses the strongest three result entries on screen.

Deployment status: the current build (room_sweep.fap) is installed at /ext/apps/Tools/room_sweep.fap and verified running on the device. The earlier launch crash was traced to a single non-existent HAL call and is fixed — see Limits & history.

03

Data flows

RF sweep loop — Path A, runs the whole time the app is open

1

Reset & load preset

Once at start: furi_hal_subghz_reset() then load the OOK 650 kHz async preset from cc1101_configs.h. This is a wide-bandwidth receive configuration, deliberately broad so it hears OOK/ASK bugs across each channel.

2

For each of 16 channels

set_frequency_and_path(freq) → rx() → sample RSSI 8 times, 5 ms apart → average → idle(). Averaging rejects impulse noise so one radar ping doesn't light the whole bar.

3

Store under mutex

Average RSSI written to rssi[ch] and sweep_ch updated while holding the app mutex — the draw callback reads the same array, so this prevents torn frames.

4

Compare to threshold

avg > −75 dBm ⇒ channel flagged. After a full pass, if any channel is hot the red LED is set (sequence_set_red_255), otherwise cleared.

5

Repeat

The loop runs until you press Back. One full 16-channel pass is ~1 second, so the chart refreshes roughly once per second.

UART pipeline — Path B, only active when the BFFB is attached

1

Own the USART

On app start the expansion-module service is disabled and the USART handle is acquired (furi_hal_serial_control_acquire), then initialised at 115200 with async RX.

2

Trigger a scan

Press OK on the WiFi tab → app sends scanap\r\n. On the BLE tab → sniffbt\r\n. State flips to Scanning….

3

ISR queues complete lines

Each byte is appended to a 128-char line buffer in the interrupt handler (no allocation). Complete lines enter a bounded pending queue; parsing stays in the main loop.

4

Screen shows parsed results

The WiFi/BLE renderer parses RSSI, identity, channel, and MAC data, then shows the three strongest entries. Marauder output such as AP: SSID Ch -60 … becomes structured state.

5

Teardown restores the bus

On exit: async RX stopped, USART deinitialised and released, expansion module re-enabled — so other GPIO apps work again afterwards.

04

User journey

What you will actually do and see, from cold start to exit. Steps 1–5 work with just the Flipper. Steps 6–8 require the BFFB ESP32.

Power on & launch

From the Flipper home screen: Apps → Tools → Room Sweep (or deploy over USB with ufbt launch, which installs and opens it for you).
You'll see: a fullscreen view. The RF Survey tab is active by default and the bar chart is already moving — sweeping starts the instant the app opens, no button press needed.

Watch the sub-GHz chart

Hold the Flipper where you'd hold a detector and slowly turn. Sixteen hollow bars rise and fall with ambient noise. The horizontal line is the −75 dBm alert threshold.
You'll see: mostly short hollow bars (ambient noise is well below threshold). Labels appear under every 4th bar (304 390 434 450).

A signal appears

Bring a transmitting source near (e.g. your own 433 MHz sensor in test mode). Its bar fills solid, SIGNAL! prints top-right, and the red LED lights.
You'll see: one or more filled bars + red LED. The source's approximate band is the bar's position on the chart. Move closer — the bar grows.

Switch tabs

Press ◀ / ▶ to cycle RF → WiFi → BLE → GPS → TX → Info and wrap around. The little strip at the very top shows which tab is active (filled = current).
You'll see: the WiFi and BLE tabs. With no BFFB attached they show the UART state as Idle when the Flipper owns the port (see what to expect).

Check the Info tab

The last tab is a live status card: version, tab/mode count, UART state, feedback state, TX state, API version, and the legal reminder.
You'll see: Room Sweep v3.0.1 · RF: 16ch ISM sweep 304-925M · TX: disarmed · API 87.1

Plug in the BFFB ESP32

Wire the ESP32's UART to the Flipper GPIO header (PC0 = Flipper TX → ESP32 RX, PC1 = Flipper RX → ESP32 TX, common ground). Power the ESP32. Relaunch the app so it acquires the UART at boot.
You'll see: on the WiFi/BLE tabs the placeholder message is replaced by Idle in the corner — the UART is now owned by the app.

Run a WiFi AP scan

On the WiFi tab press OK. The app sends scanap and the status changes to Scanning….
You'll see: Marauder result lines scroll in from the top, e.g. AP: YourNetwork Ch:6 RSSI:-52 MAC:aa:bb:…. The three strongest parsed entries are shown.

Run a BLE sniff, then exit

Move to the BLE tab and press OK to send sniffbt. When done, use Short Back for Settings or Long Back to exit. On exit the app stops the RF thread, releases the UART, re-enables the expansion module, and returns to the app list.
You'll see: BLE advertisements (MACs / names) scrolling. After exit, the red LED is cleared and other GPIO apps work normally again.

What to expect

SituationRF tabWiFi / BLE tabs
Flipper only (no BFFB) Live bar chart, ~1 pass/sec. Ambient bars stay hollow and short. Usually shows Idle — the UART is owned by the app even with nothing plugged in. No lines appear because nothing is transmitting. See the note below.
BFFB attached, scan not started Unchanged. Idle in the corner, empty list.
BFFB attached, OK pressed Unchanged. Scanning… / Sniffing…, result lines streaming.
UART acquisition fails (another app/expansion holds it) Unchanged. No UART state; acquisition is unavailable.
Scan stays silent for 30 seconds Unchanged. ERR appears and the scan is stopped. With Auto-Rescan enabled, the app retries after the rescan interval.
Honest caveat about "BFFB not connected": the app detects "UART available," not "ESP32 present." Because the Flipper's USART exists on its own GPIO header, acquisition succeeds even with the BFFB unplugged — so you'll see Idle, not the placeholder. The reliable tell that the BFFB is really talking is result lines appearing after you press OK. If nothing streams, check wiring/baud before assuming a software fault.

Reading the RF chart

Hollow bar

RSSI below −75 dBm. Normal ambient noise, distant transmitters, or nothing. This is the resting state.

Solid bar + SIGNAL! + red LED

Average RSSI above −75 dBm on that channel. Something nearby is transmitting in that band. The bar's horizontal position tells you roughly where in the spectrum.

Realistic expectations

  • It will alert on legitimate stuff. Your own routers, keyfobs, weather sensors, and neighbouring WiFi all look like "signals." Sweep in a known-quiet spot first to learn your baseline.
  • RSSI is a detector, not a locator. A tall bar means "energy here," not distance. To locate, move and watch the bar grow/shrink.
  • Sub-GHz only sees analog/OOK transmitters. A modern WiFi-only bug or an LTE tracker will not light the RF chart — that's what the BFFB WiFi/BLE path is for.

Development history — the launch crash

An earlier build rebooted the Flipper the instant it launched. Root cause: the code called furi_hal_subghz_load_preset(), a function that does not exist in any Flipper firmware. The FAP loader couldn't resolve the symbol and hard-faulted. The fix was one line — load the preset from the CC1101 config table instead:

// WRONG — symbol does not exist:
furi_hal_subghz_load_preset(FuriHalSubGhzPresetOok650Async);

// CORRECT:
#include <lib/subghz/devices/cc1101_configs.h>
furi_hal_subghz_load_custom_preset(subghz_device_cc1101_preset_ook_650khz_async_regs);

Every API call in the current source has since been checked against the Momentum api_symbols.csv export table (API 87.1, ~2,400 functions), and the build compiles with zero warnings and a matching API tag.

Legal & safety

Use on property you own or have written authorization to assess. Passive reception of RF energy is broadly lawful in most jurisdictions, but scanning for / enumerating WiFi networks and Bluetooth devices that aren't yours can run afoul of computer-misuse and wiretap statutes depending on where you are. This tool is a detector for your rooms, your lab.
  • TX is separate and gated. It starts disarmed, requires OK to arm and Long-OK to transmit, is time-bounded, and can be disarmed with Back. Use only on your own equipment and within applicable rules.
  • It captures metadata, not content. Marauder in this configuration reports SSIDs, MACs, channels, and RSSI — it does not crack handshakes or read traffic.
  • Findings stay private. If you sweep a shared/rented space, you may learn things about neighbours. Treat that data as confidential and act only on your own property.

Build & deploy

Uses the installed ufbt (micro Flipper Build Tool) against the Momentum SDK.

shell# from the project root
cd ~/sw33p3r

ufbt          # build  → dist/room_sweep.fap  (API 87.1, zero warnings)
ufbt launch   # install to /ext/apps/Tools/ + open on device
Deploy gotcha: Room Sweep is a fullscreen app, so while it's running the CLI can't close it with loader close and ufbt launch fails with "has to be closed manually." To redeploy while it's open, send the complete input send back press → long → release sequence, then rerun ufbt launch.

To change the swept channels or the alert threshold, edit room_sweep.h (rf_channels[] and RF_ALERT_THRESHOLD) and rebuild. Keep every frequency inside a CC1101 band.
